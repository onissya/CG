## Подробное объяснение для защиты

### Коротко о работе

Это веб-приложение для визуализации двух алгоритмов отсечения из варианта 17:

1. алгоритм Лианга-Барски для отсечения отрезков;
2. алгоритм отсечения выпуклого многоугольника. В программе используется метод Сазерленда-Ходжмана.

Пользователь задаёт координаты прямоугольного окна, список отрезков или вершины многоугольника. Программа проверяет ввод, запускает алгоритм, выводит координаты результата и рисует исходную и видимую части на Canvas.

- src/types.ts - типы точки, отрезка, окна и многоугольника;
- src/algorithms.ts - математические алгоритмы;
- src/algorithms.test.ts - автоматические тесты;
- src/main.ts - форма, обработка ввода, Canvas и таблицы;

## Типы данных

В types.ts описаны основные сущности.

Точка:

~~~ts
export interface Point {
  x: number;
  y: number;
}
~~~

Отрезок состоит из двух точек:

~~~ts
export interface Segment {
  start: Point;
  end: Point;
}
~~~

Окно отсечения:

~~~ts
export interface ClipWindow {
  xmin: number;
  ymin: number;
  xmax: number;
  ymax: number;
}
~~~

Окно задаётся ограничениями:

~~~text
xmin <= x <= xmax
ymin <= y <= ymax
~~~

Многоугольник - это массив вершин:

~~~ts
export type Polygon = Point[];
~~~

Для результата отсечения отрезка дополнительно хранятся параметры входа и выхода:

~~~ts
export interface ClippedSegment extends Segment {
  tEnter: number;
  tLeave: number;
}
~~~

## Математическая модель

Прямоугольное окно задаётся так:

~~~text
W = [Xmin, Xmax] x [Ymin, Ymax]
~~~

Отрезок задаётся параметрически:

~~~text
P(t) = P1 + t(P2 - P1), 0 <= t <= 1
~~~

В координатной форме:

~~~text
x(t) = x1 + t(x2 - x1)
y(t) = y1 + t(y2 - y1)
~~~

Значение t = 0 соответствует началу отрезка, t = 1 - концу, а промежуточные значения - точкам между ними.

Для множества отрезков:

~~~text
S = {s1, s2, ..., sn}
~~~

Каждый отрезок обрабатывается отдельно. Результатом может быть новая пара точек или отсутствие видимой части.

Для многоугольника:

~~~text
P = (A1, A2, ..., Am)
~~~

Он последовательно пересекается с четырьмя полуплоскостями окна:

~~~text
P0 = P
P1 = Clip(P0, left)
P2 = Clip(P1, right)
P3 = Clip(P2, bottom)
P4 = Clip(P3, top)
~~~

Для Canvas используется преобразование:

~~~text
u = u0 + x * scale
v = v0 - y * scale
~~~

Минус перед y нужен потому, что в математической системе координат Y растёт вверх, а в Canvas экранная координата растёт вниз.

## Алгоритм Лианга-Барски

Алгоритм находится в src/algorithms.ts. Основная функция:

~~~ts
clipSegmentLiangBarsky(segment, rawWindow)
~~~

Она возвращает отсечённый отрезок или null, если исходный отрезок полностью находится за пределами окна.

Сначала вычисляются приращения:

~~~ts
const dx = segment.end.x - segment.start.x;
const dy = segment.end.y - segment.start.y;
~~~

Для четырёх границ строятся массивы:

~~~ts
const p = [-dx, dx, -dy, dy];

const q = [
  segment.start.x - window.xmin,
  window.xmax - segment.start.x,
  segment.start.y - window.ymin,
  window.ymax - segment.start.y,
];
~~~

Эти значения приводят ограничения к виду:

~~~text
p[i] * t <= q[i]
~~~

В начале считается, что виден весь отрезок:

~~~ts
let tEnter = 0;
let tLeave = 1;
~~~

Если p[i] < 0, это ограничение на вход в окно:

~~~ts
tEnter = Math.max(tEnter, parameter);
~~~

Если p[i] > 0, это ограничение на выход:

~~~ts
tLeave = Math.min(tLeave, parameter);
~~~

Если tEnter больше tLeave, общий видимый интервал отсутствует:

~~~ts
return null;
~~~

Иначе вычисляются новые концы:

~~~ts
start = P(tEnter)
end = P(tLeave)
~~~

### Пример Лианга-Барски

Окно:

~~~text
xmin = -5, xmax = 5
ymin = -5, ymax = 5
~~~

Отрезок:

~~~text
A(-10, 0), B(10, 0)
~~~

Параметрическое уравнение:

~~~text
x(t) = -10 + 20t
~~~

Левая граница:

~~~text
-10 + 20t = -5
t = 0.25
~~~

Правая граница:

~~~text
-10 + 20t = 5
t = 0.75
~~~

Следовательно:

~~~text
tEnter = 0.25
tLeave = 0.75
P(0.25) = (-5, 0)
P(0.75) = (5, 0)
~~~

Видимая часть - отрезок от (-5, 0) до (5, 0).

### Особый случай p = 0

Если p равен нулю, отрезок параллелен соответствующей границе.

- Если он находится снаружи, возвращается null.
- Если он находится внутри или на границе, эта граница не ограничивает параметр t.

EPSILON нужен для защиты от погрешностей вычислений с дробными числами.

### Сложность

Для одного отрезка всегда проверяются четыре границы, поэтому сложность равна O(1). Для n отрезков общая сложность равна O(n).

## Алгоритм отсечения выпуклого многоугольника

Функция находится в src/algorithms.ts:

~~~ts
clipConvexPolygonSutherlandHodgman(polygon, rawWindow)
~~~

Используется алгоритм Сазерленда-Ходжмана. Он последовательно обрабатывает границы:

~~~ts
const boundaries = ["left", "right", "bottom", "top"];
~~~

Для каждой пары соседних вершин возможны четыре ситуации.

1. Обе вершины внутри. В результат добавляется конечная вершина.
2. Начальная внутри, конечная снаружи. Добавляется точка пересечения.
3. Начальная снаружи, конечная внутри. Добавляется точка пересечения и конечная вершина.
4. Обе вершины снаружи. Ничего не добавляется.

В коде это реализовано так:

~~~ts
if (endInside) {
  if (!startInside) {
    output.push(intersection(start, end, window, boundary));
  }

  output.push(end);
} else if (startInside) {
  output.push(intersection(start, end, window, boundary));
}
~~~

Перед циклом начальной вершиной берётся последняя:

~~~ts
let start = input[input.length - 1];
~~~

Это нужно, чтобы обработать замыкающее ребро между последней и первой вершинами.

### Поиск пересечения

Для вертикальной границы фиксируется x:

~~~text
t = (xBoundary - x1) / (x2 - x1)
y = y1 + t(y2 - y1)
~~~

Для горизонтальной границы фиксируется y:

~~~text
t = (yBoundary - y1) / (y2 - y1)
x = x1 + t(x2 - x1)
~~~

После каждого прохода одинаковые соседние вершины удаляются, чтобы в результате не было дубликатов.

### Сложность

Если в многоугольнике m вершин, четыре прохода дают O(4m), что эквивалентно O(m).

## Логика интерфейса

В main.ts создаётся форма с двумя режимами:

- отрезки - Лианг-Барски;
- выпуклый многоугольник.

Функция readWindow() считывает xmin, ymin, xmax и ymax, проверяет числа и нормализует границы.

Функция parseRows() разбирает строки textarea.

Для отрезков ожидается:

~~~text
x1 y1 x2 y2
~~~

Для вершин многоугольника:

~~~text
x y
~~~

Если строка содержит неправильное количество значений или текст, выводится ошибка с номером строки.

Главная функция run():

1. считывает окно;
2. определяет выбранный режим;
3. разбирает исходную геометрию;
4. вызывает нужный алгоритм;
5. сохраняет результат;
6. перерисовывает Canvas;
7. обновляет таблицу;
8. выводит статус расчёта.

Для нескольких отрезков алгоритм вызывается отдельно:

~~~ts
const clippedSegments = segments.map((segment) =>
  clipSegmentLiangBarsky(segment, window)
);
~~~

## Canvas и система координат

Canvas использует центр как начало координат. Формула преобразования:

~~~ts
[
  canvas.width / 2 + point.x * scale,
  canvas.height / 2 - point.y * scale,
]
~~~

Функция drawGrid() рисует сетку, оси и подписи координат.

Функция drawScene() рисует:

1. окно отсечения;
2. исходные отрезки или многоугольник;
3. видимые части.

Изменение масштаба влияет только на внешний вид. Математический результат алгоритмов от масштаба не зависит.

## Автоматические тесты

Тесты находятся в src/algorithms.test.ts. Всего проверяется 7 сценариев.

### 1. Отрезок полностью внутри

Проверяется, что отрезок возвращается без изменений.

### 2. Отрезок пересекает окно

Для отрезка (-10, 0) - (10, 0) проверяются новые концы (-5, 0) и (5, 0), а также tEnter = 0.25 и tLeave = 0.75.

### 3. Невидимый, вертикальный и вырожденный отрезки

Проверяются:

- отрезок полностью снаружи;
- вертикальный отрезок, где dx = 0;
- точка внутри окна;
- точка снаружи окна.

### 4. Обратный порядок границ

Проверяется, что xmin и xmax, введённые наоборот, нормализуются.

### 5. Квадрат пересекает все границы

Большой квадрат должен превратиться в квадрат по границам окна. Проверяются четыре ожидаемые вершины.

Порядок вершин не фиксируется, потому что алгоритм может начать возвращённый контур с другой вершины.

### 6. Многоугольник внутри окна

Результат должен совпадать с исходным многоугольником.

### 7. Многоугольник снаружи

Ожидается пустой массив вершин.

Для сравнения дробных координат используется toBeCloseTo, потому что операции пересечения могут давать небольшую погрешность.

## Готовые ответы на защите

### Почему выбран Лианг-Барски?

Потому что для 17 варианта в первой части требуется алгоритм Лианга-Барски через параметрическое задание отрезка.

### В чём преимущество Лианга-Барски?

Он сразу вычисляет интервал параметра t, в котором отрезок находится внутри окна. Не нужно пошагово проверять точки отрезка.

### Что такое tEnter и tLeave?

tEnter - параметр входа отрезка в окно. tLeave - параметр выхода из окна.

### Что означает null?

Отрезок полностью находится вне окна и не имеет видимой части.

### Что происходит при p = 0?

Отрезок параллелен текущей границе. Если он снаружи, возвращается null. Если внутри, эта граница не ограничивает параметр t.

### Зачем нужен EPSILON?

Для сравнения дробных чисел с нулём и защиты от ошибок округления.

### Как работает отсечение многоугольника?

Многоугольник последовательно обрабатывается относительно четырёх границ окна. Для каждой пары вершин определяется, находятся ли они внутри или снаружи. В зависимости от перехода добавляются вершины и точки пересечения.

### Почему берётся последняя вершина?

Чтобы обработать замыкающее ребро между последней и первой вершинами.

### Почему удаляются дубликаты?

Одна и та же точка на границе может добавиться от двух соседних рёбер. Дубликаты удаляются для корректного списка вершин.

### Почему ось Y инвертируется?

В математической системе координат Y растёт вверх, а в Canvas экранная координата растёт вниз. Поэтому используется формула v = v0 - y * scale.

### Что проверяли тесты?

Проверялись видимый, пересекающий и невидимый отрезки, вертикальный и вырожденный случаи, обратные границы окна, многоугольник внутри окна, многоугольник снаружи и квадрат, пересекающий все четыре границы.
